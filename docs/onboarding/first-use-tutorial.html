Getting started with Threshold

A first-use tour over real screenshots of the app: from an empty Home screen to your first Random Window alarm. Pick your platform, then step through — or switch to Overview to see every callout at once.

How this tutorial was designed — concepts considered and ranked

Five distinct onboarding formats were sketched before building. Each was scored 1–5 on ease of use (for a brand-new user), practicality (how realistic it is to ship and maintain inside the real app) and coolness. The winner is a deliberate synthesis: the linear coach-mark stepper as the spine, with the poster's "see everything at once" mode and the hotspot map's jump-anywhere navigation folded in.

Choice. Concept 1 won on the two scores that matter most for a first run — ease and practicality — so it is the default view here. Its weakness (a single fixed path) is patched by borrowing from the runners-up: the Overview toggle is concept 2's poster, and the screen chips plus the clickable progress dots are concept 5's jump-anywhere navigation. Concept 3 scored highest on coolness but its sticky-scroll mechanics are exactly the kind of thing that breaks on a 412-pixel phone, which is where half of Threshold's users are.

Desktop and Android as one file. The flow is identical on both platforms (Home → Add → Window mode → Save → Settings); only the screenshots, the chrome and a handful of element positions differ. Sharing one annotation engine and one step list per platform keeps the two in sync — the Desktop/Android switch simply swaps the screenshot set and the coordinate table.

How the screenshots were captured

Every image is a real render of the app's React/MUI source, not a mock-up. The frontend was served by Vite with Tauri's IPC replaced by mockIPC() from @tauri-apps/api/mocks — the same invoke() the services call, answered by an in-memory alarm store seeded with one Fixed Time and one Window alarm. Desktop frames are 760 × 680, the app's fixed window size; Android frames are 412 × 915 with platform() reporting android, which is what flips the app into its mobile layout (top app bar, floating action button, Material time fields, swipe-to-delete rows). Both were captured in a headless Chromium at 1× CSS pixels and embedded here as base64 so the file has no external dependencies.

The harness lives in apps/threshold/dev-harness/ with apps/threshold/vite.harness.config.ts; run pnpm --filter threshold exec vite --config vite.harness.config.ts and open /dev-harness/index.html?seed=empty&platform=android.
